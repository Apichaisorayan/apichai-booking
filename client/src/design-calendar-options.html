Design ปัจจุบัน

แต่ละ segment แยกเป็น block อิสระ — Consultation, Preparation, Doctor Treatment, Machine Active

✅ จุดดี

  • แสดง segment ครบทุกขั้นตอน
  • มี Badge บอก type ของแต่ละ segment
  • Drag & Drop ย้ายเวลาได้

❌ ปัญหาสำหรับแพทย์

  • Segments แยกกัน ดูเหมือนหลาย event
  • ไม่มีชื่อผู้ป่วยบน event card
  • แพทย์ต้องตีความเองว่าช่วงไหน busy/free
  • Appointment ที่ overlap ดูสับสน
  • สีไม่ช่วยแยก busy vs free ชัดเจน

  • เห็นชื่อผู้ป่วย + procedure ชัดเจน

❌ ข้อเสีย

  • ต้องสร้าง view ใหม่ทั้งหมด (งานเยอะ)
  • ถ้ามีหมอหลายคน column จะแคบ
  • ไม่เห็นข้อมูลห้อง/เครื่องมือชัดเจน (เน้นหมอ)
  • Drag & Drop ต้อง redesign

Option B: Unified Card IMPROVE

รวม segments เป็น card เดียว — ภายในแบ่งแถบสี busy/free — ชื่อผู้ป่วยเด่นชัด

✅ ข้อดี

  • 1 appointment = 1 card — ไม่สับสน
  • ชื่อผู้ป่วย + procedure เด่นชัดที่ header
  • แถบสีภายใน card บอก busy/free ชัดเจน
  • แก้ไขจาก code เดิมได้ง่าย (ปรับ renderDayView)
  • Drag & Drop ยังใช้ได้เหมือนเดิม

❌ ข้อเสีย

  • Card ยาว อาจบังเวลาอื่น
  • ยังไม่ได้จัดกลุ่มตามหมอ (ต้องหาจาก card)
  • Overlap ของ card อาจซับซ้อน

Option C: Busy Indicator IMPROVE

คง layout เดิม — เพิ่มแถบสีด้านข้าง (แดง=busy, เขียว=free) + เพิ่มชื่อผู้ป่วย

✅ ข้อดี

  • แก้ไขน้อยที่สุด — เพิ่มแค่ strip สี + ชื่อผู้ป่วย
  • ไม่เปลี่ยน layout เดิม ผู้ใช้ไม่ต้องเรียนรู้ใหม่
  • แถบแดง/เขียว เข้าใจง่าย
  • Drag & Drop ยังทำงานเหมือนเดิม

❌ ข้อเสีย

  • Segments ยังแยกกัน — ยังดูเหมือนหลาย event
  • ปรับปรุงน้อย อาจไม่ช่วยเรื่อง UX มากนัก
  • ยังไม่ได้จัดกลุ่มตามหมอ

Option D: Doctor Timeline + Unified Card BEST

รวมจุดเด่นของ A + B — จัดกลุ่มตามหมอ + card รวม segments + ชื่อผู้ป่วยเด่น

✅ ข้อดี

  • ดีที่สุดสำหรับแพทย์ — เห็น column ตัวเอง + card รวมครบ
  • 1 card = 1 appointment พร้อมแถบ busy/free
  • ชื่อผู้ป่วย + procedure เด่นชัด
  • เปรียบเทียบตารางหมอหลายคนได้

❌ ข้อเสีย

  • งานเยอะที่สุด (สร้าง view ใหม่ + redesign card)
  • อาจเป็น view เสริม ไม่ใช่ default
  • Column แคบถ้ามีหมอหลายคน
